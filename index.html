How I build platforms

1. Build the path once, so ten teams don't file ten tickets

If a developer needs a ticket to deploy, get a namespace, or rotate a certificate, the platform has failed. I ship that path once — GitOps, policy checks, and rollback built in — and then ten teams use it without ten tickets.

2. Optimise for time-to-fix, not time-to-dashboard

Dashboards don't fix incidents. SLO burn, mesh traffic, and evidence do. I alert on budget burn, not noise, and I start every incident with data — gateway, certificate, endpoint, pod — in that order, so we don't restart things and hope.

3. Automate the second occurrence, never just the first fire

The first time something breaks, you fix it. The second time, it should already be written down, searchable, and ideally self-diagnosed. That's why incident memory and the agentic responder exist here — to make the second occurrence faster than the first, not just to add another tool.
